# v0.3.0 (tagged, GitHub Release not published)

To get the new button, add `https://github.com/meryzennn/orca-discord-rpc.git#v0.3.0` in Settings > Plugins > Add Plugin and review the new command. You do not need to uninstall the same Git plugin first. Disable or remove any development copy so only one provider runs.

## Added

- **Update RPC** in the status bar and **Discord RPC: Update installed plugin** in the command palette. These call Orca's updater for the published Git installation and report current, updated, pinned, unsupported-host and error states.
- The button requires **Orca application 1.4.253+**. On 1.4.250, presence keeps working and the button explains the upgrade requirement.
- Repeated clicks share one request. The command returns immediately and update failures do not pause presence. Updates that need more access remain pending user review in Orca; the button never passes an approval flag.
- `node src/cli.ts update` for headless checkouts. It refuses tracked edits or nested source folders, uses a fast-forward pull and restarts a running daemon only when files changed.

## Update behavior

Checks run on click, with no background update timer. Version-tag installs follow the newest tag; branch installs follow their newest commit; commit pins stay fixed. Development folders are not self-updated.

An installed update restarts the worker and starts a new elapsed session. An up-to-date check or refused update leaves the current presence alone. RPC settings remain owned by Orca.

## Verification

- Tests cover native updater result/error parsing, literal subprocess arguments, no automatic approval, click coalescing, non-blocking shutdown and RPC continuity.
- A separate Git checkout and test daemon verify fast-forward updates, restart after a change, no-op behavior and refusal without losing local edits or commits.
- The unsupported-host message was checked against the installed Orca 1.4.250. Successful native plugin installation on Orca 1.4.253+ still needs a live-host check.
